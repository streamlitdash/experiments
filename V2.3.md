# V2.3 — Minimal cold-start rendering fix

## Goal

Make Rebirth V4.1 follow the successful Final Test startup pattern:

```text
commit financial revision 1
-> mount a light page containing empty Risk and Aggregate P&L containers
-> ignore revision 0 and stale callback requests
-> publish revision 1 to the browser
-> build Risk once and Aggregate P&L once
```

This guide is based on Rebirth V4.1 `main` at commit `cdf1e77`.

The current slow path is:

```text
commit revision 1
-> build Risk and Aggregate P&L inside build_layout()
-> mount the page with data revision 0
-> callbacks may build the tables at revision 0
-> browser publishes revision 1
-> callbacks may build the tables again
```

Do the first four changes together. They are small and preserve all financial
calculations, filters, tables and interactions.

## Step 1 — Stop building both tables inside the page layout

File:

```text
rebirth/pages/risk/s16_view.py
```

Open `build_layout()` and find the block beginning with:

```python

initial_filter_payload = default_risk_filter_payload(risk_data)
```

Keep this line:

```python
initial_filter_values = default_risk_filter_values(risk_data)
```

Delete `initial_filter_payload` and the complete eager calculation beginning at:

```python
initial_risk_type = risk_options[0]["value"]
```

and ending after:

```python
initial_aggregate_table = build_aggregate_pl_table(...)
```

Replace that calculation with only:

```python

initial_risk_table = None
initial_aggregate_table = None
```

Leave the existing `risk-grid` and `aggregate-pl-grid` containers in the layout.
Passing `None` means they mount as empty placeholders and their existing callbacks
remain the sole table builders.

Remove the imports that this deleted block no longer uses:

```python

apply_filters
default_open_rows
filter_ir_family
build_aggregate_pl_table
default_risk_filter_payload
build_risk_table
```

Keep `CREDIT_MEASURES`, `DEFAULT_UNDERLYING_SORT_METRIC` and `ordered_unique`.
They are still used by the controls.

## Step 2 — Do not build Risk for revision 0 or a stale revision

File:

```text
rebirth/pages/risk/s07_explorer.py
```

At the beginning of `reduce_and_render_risk_view()`, before any cache or
DataFrame work, add:

```python
if refresh_manager is not None and int(data_revision or 0) != int(
    refresh_manager.health.revision
):
    raise PreventUpdate
```

`PreventUpdate` is already imported in this file.

Why use equality instead of only checking for zero:

- revision `0` cannot build a committed table;
- revision `1` builds revision `1` exactly once;
- after a later refresh, an old revision cannot rebuild a stale table.

Do not add `prevent_initial_call=True` as the only protection. The persistent
revision Store exists before the Risk page is inserted dynamically, so an
initial callback can still occur when the page mounts.

After Steps 1–3, the sequence is:

```text

-> both callbacks stop immediately without reading the large frame
-> assets/s12_refresh.js publishes committed revision 1
-> Risk callback builds once
-> Aggregate P&L callback builds once
```

Do not change `assets/s12_refresh.js` for this fix. Its existing revision handoff
can remain.

## Step 4 — Stop the shared shell copying every financial frame

File:

```text
rebirth/pages/risk/s15_refresh.py
```

Inside `hydrate_shared_refresh_shell()`, find the successful-startup call:

```python

```

Change only that argument:


The shared shell needs dates, revision, readiness and settings only.

dashboard and unmapped frames. `control_snapshot` does not.

Do not change the separate `refresh_manager.snapshot` passed to
`materialize_initial_dashboard()`. That path genuinely needs the dashboard
frame.

## Step 8 — Measure before changing financial release

The message `Combining, validating and atomically publishing the snapshot` is
broad. It includes release mapping, promotion, validation and SearchCatalog
construction. The actual atomic pointer replacement is very small.

After Steps 1–7, inspect the existing timing output:

- long `market` time means the real adapter/concurrency path is slow;
- long `release` time means mappings, promotion or validation are slow;
- long `search` time means SearchCatalog construction is slow;
- fast refresh followed by a slow page means hydration was the problem.

Do not delete Cross Gamma, New Trades, release validation or raw-underlying
search merely to make the timer smaller. That would remove application capacity.

If `release` is still materially slow, make a separate commit that replaces the
two position-level merges in
`rebirth/domain/s07_governance.py::_apply_validated_thresholds()` with:

```text
one small identity-level enrichment build
-> one many-to-one merge back to the position frame
```

That change must preserve:

- threshold values on Activities outside 1–3;
- neutral promotion for identities that exist only outside Activities 1–3;
- unmapped rows;
- exact row order and row count;
- Risk, dRisk and P&L totals.

Use `tests/s14_reporting.py` as the financial equivalence gate. Keep this
optimisation separate from the rendering fix so it can be measured and reverted
independently.

## Do not remove

Keep:

- the single startup writer;
- atomic snapshot publication;
- the last-good snapshot;
- connector and release validation;
- revision consistency checks;
- merge-cardinality checks;
- missing-market handling; and
- raw versus reported Underlying authority.

These protections are not the cause of the repeated first-page rendering.
